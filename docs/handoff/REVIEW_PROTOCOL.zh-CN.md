# 实现与独立审计协议

本协议用于 Claude Code / Kimi 实现、Codex 审计的本地协作。代码和报告是共享上下文；不依赖聊天记录和自动转发。用户后续明确指令优先。

## 状态与责任

```text
ready → implementing → ready_for_review → accepted
                         ↓
                   changes_requested → implementing

任意实施阶段 → blocked_environment（记录可交付部分和缺口，不能算 accepted）
```

实现者在 implementation 报告记录状态；审计者在独立 review 报告记录结论。后者才决定是否通过。报告以任务 ID、base SHA、被审计 head SHA 关联。代码随后变化，旧审计结论不能自动覆盖新提交。

## 实现者交付

按 [报告模板](REPORT_TEMPLATE.md) 创建 `reports/T01-implementation.md` 或 T02 对应文件。至少包含基线、最后代码提交、变更文件、契约偏离、测试环境/命令/结果、待解决项与 token 数据（没有则 unknown）。报告随后单独提交；最终回复给出含报告的 HEAD，避免在报告内填写自身提交 SHA 形成自引用。

首次交付不 squash；修复审计问题追加提交并逐项回应。一个问题对应修复、回归用例或有依据的异议。没有测试数据或日志时不得编写“通过”。不要为凑 66/更多测试数量写镜像实现的断言。

## Codex 审计步骤

1. 先读新项目 AGENTS、status、当前任务卡和实现报告。确认工作树状态以及分支/base/head；不重读全部历史调研。
2. 检查 `git diff <base>..<head> --stat` 与实际 diff，关注新增/删除文件、迁移和依赖变化。基线必须存在并是 head 的祖先。报告与实际代码不符时优先核查。
3. 沿关键调用链核对契约。T01 着重事务原子性、可信 actor、回填和前端草稿；T02 着重真实 dialect、迁移执行顺序、隔离库保护与恢复证据。
4. 独立运行与风险相匹配的测试。复用已有依赖、使用隔离测试数据，不重放整个安装过程；必要时补充能暴露缺陷的回归用例。不能只读实现者“all passed”文字。
5. 列出具体问题：严重程度、文件/符号、触发条件、后果、建议验证。区分阻断缺陷和非阻断改进；不把审计变成无关格式重写。
6. 写 `reports/T01-review.md`（后续类推），引用被审计的准确 head。结论为 accepted / changes_requested / blocked_environment，说明实际独立验证范围及未覆盖风险。

测试端口/服务与用户开发环境隔离。若共享目录的实现者还在修改，先由用户协调交付边界或使用独立 worktree；不要同时 checkout 同一工作目录。没有证据时不从“测试没报错”推断云部署已经可用。

## 阻断标准

- 越权、凭据泄漏、数据丢失、绕过只读边界：必须修复后才能通过。
- 错误版本判断、事务不完整、迁移丢现有数据、实际 UI 丢草稿、必需检查失败：必须修复。
- 任务明确要求的运行环境未验证：blocked_environment，不能用“已写 CI”替代。
- 不影响验收的文案/组织改进可入后续清单，不强制扩大本次范围。

审计不是保证不存在所有问题。记录覆盖范围；T01 通过只说明当前 SQLite/API/UI 约定通过，PostgreSQL 验证继续归 T02。

## 整合与下一包

accepted 后由 Codex 本地整合到 main，保留实现与审计提交；优先 fast-forward，出现分歧时核查双方变更，不能强制重置 main。整合后更新 docs/status.md 的实际功能和待办，而非直接删除所有旧限制。无需远端 push。

用户把审计结论或报告路径交给 Claude Code，即可继续修复或开始下一张已指定任务卡。T02 accepted 后先用两包成本数据调整分工；T03 已有 TASK-03-repository-identity.zh-CN.md，但实施仍等待 T02 accepted 与整合；T04 以后仅有路线图，实施前另定任务契约，不自动连续做完全部功能。

## 成本比较口径

按“已验收任务”统计：设计、实现、自测、审计和返工都算入。记录模型实际名称与计费来源；输入、缓存输入、输出/推理、费用分别记录，缓存字段是否已包含在 input_total 中也要说明，不能重复相加。

订阅额度和 API 金额分别展示；币种/计费日期不混用。未知字段写 unknown；工具下载等待不折算为模型 token。除了费用，比较首轮阻断缺陷数、修复轮数和实际人类介入次数。连续两轮仍无法满足同一核心契约时，先缩小任务或由 Codex接手该部分，再继续花 token。

首批结束只形成两任务样本的判断，不把它推断为所有模型或所有工程场景的通用能力排名。
